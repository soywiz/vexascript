# 0.10.0 release preparation and version boundaries

## Evidence

The repository entered release preparation at package version `0.9.4` with a
clean worktree. The native release candidate was commit `bac80503` from
2026-07-24, and the package release was finalized in commit `3ef03875` on
2026-07-25. The range since `59d87d40` contains 125 non-merge commits. The
work is broad enough for a minor release: the native C++ command group, cached
executable workflow, Oilpan runtime, cross-backend FFI, self-hosting checks,
and Windows packaging validation are all covered by the current test suite.

The root `package.json` supplies `COMPILER_VERSION` to the CLI, LSP, and MCP
surfaces. The VS Code extension has a separate `plugins/vscode/package.json`
version, so preparing 0.10.0 required updating both files. The root lockfile
does not duplicate the package version. `node dist/vexa.js --version` and
`pnpm pack --dry-run` confirmed the resulting package metadata and native
artifacts.

## Process gap

There is no release manifest, changelog, or tag workflow. This preparation adds
an automated packaging assertion that the root package and VS Code extension
versions match, while publishing and tagging remain intentionally separate
operations. A future release task could add a guarded release checklist without
making package publication part of ordinary test runs.

## Investigation notes

The website build generated the expected 0.10.0 page and also left unrelated
working-tree changes in syntax-highlighting sources. Those changes were
preserved rather than folded into the release diff. A full-page browser
screenshot appeared to omit the article and repeat the header, but viewport
inspection showed the article at the correct coordinates with no horizontal
overflow; a normal viewport screenshot displayed the rendered article. The
artifact was a screenshot limitation, not a website layout regression.
